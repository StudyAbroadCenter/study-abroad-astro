# RSJP Experience System — Roadmap

This roadmap describes direction, not guaranteed delivery dates.

Do not convert roadmap items into commitments without explicit approval.

## Phase 0 — Foundation

Objective:
Create a clear product and implementation framework.

Includes:
- principles,
- project specification,
- brand,
- UX,
- design,
- content,
- components,
- data,
- SEO,
- technical direction,
- decision log.

Status should be updated explicitly by the project owner; do not infer completion from the existence of this file.

## Phase 1 — Recruitment MVP

Objective:
Ship a high-quality, mobile-first recruitment website.

Priorities:
- programme discovery,
- programme pages,
- verified facts,
- accommodation,
- FAQ,
- application guidance,
- strong performance,
- accessibility,
- authentic photography.

Constraints:
- no CMS unless separately approved,
- no speculative backend,
- no unnecessary feature expansion.

## Phase 2 — Stabilisation and Evidence

Objective:
Improve based on real use.

Potential work:
- accessibility review,
- performance tuning,
- search/indexing improvements,
- applicant feedback analysis,
- repetitive-enquiry analysis,
- content refinements,
- component consolidation where repeated patterns are proven.

Do not invent analytics results.

## Phase 3 — Multilingual Expansion

Potential goals:
- stronger English editorial experience,
- additional language versions where justified,
- shared fact model,
- language-specific content workflow,
- international SEO.

Language rollout must be based on operational capacity and programme strategy.

## Phase 4 — CMS Evaluation

Evaluate CMS only when current content operations create a real maintenance problem.

Decision criteria may include:
- number of programmes,
- update frequency,
- number of editors,
- approval workflow,
- multilingual complexity,
- audit/version needs.

A CMS is not automatically the next phase.

## Phase 5 — Operational Integration

Possible future capabilities:
- application workflow integration,
- programme-data management,
- staff editing workflow,
- approved automation,
- dashboards.

Each capability requires a separate product and security decision.

## Phase 6 — Experience Platform

Long-term possibility:
extend the framework beyond recruitment into a broader short-term programme digital experience.

This is not an MVP commitment.

## Roadmap Rules

- No dates without explicit project approval.
- No feature becomes "planned" merely because it is technically possible.
- Every phase must preserve truth, trust, and student-first UX.
- Review `11_DECISIONS.md` before reversing earlier scope decisions.
